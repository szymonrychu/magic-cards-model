  Fixed in aced3857 (cached straight-line runner per segment, 5.58 s). m1's ported-branch
  cheap gate also had 1 failed test that did not reproduce on a rerun; its id was lost, so
  1749df1a makes the measurement record failing test ids. The r4 baseline later named the
  load-sensitive one: tests/test_card_support.py::test_the_full_pool_classifies_within_budget
  failed once at machine load 15 (pre-existing engine test, untouched).
- r2 (full, 519927a2): baseline, F1 and F2 (cheap + full, test_dispatch_order) green; the
  F3 cheap gate failed import time (+19.7%) and suite wall time (222 s -> 436 s) while other
  sessions' suites held the machine at load 36 on 12 cores. Aborted. An experiment (effects
  sweep alone vs beside 24 busy loops) gave wall 6.5 s -> 15.6 s, CPU 6.5 s -> 6.6 s:
  2a59de57 makes the timing gates compare CPU time when both sides have it.
- r3 (full, 519927a2): baseline measured at load 12-30 (test 359 s wall), so every later
  wall gate would have passed trivially. Aborted when 2a59de57 landed.
- r4 (full, 2a59de57): baseline, F1 and F2 cheap green, F1 full green; import CPU time at
  F1 read +14.6% (r2 had +3% wall), the median of 5 still moving with load 8-17. Aborted;
  b0da375b gates the minimum CPU time of 7 runs (three back-to-back measurements at load 26:
  488/494/492 ms).
- r5 and r6 (full, b0da375b): the pair counted for the freeze. Limit seen in both: CPU time
  on this 8P+4E machine still drifts with load (the r5 monolith `mise run test` ran at load
  23 and read 1463 s CPU against about 1200 s at later quieter steps), so a baseline taken
  under load makes the suite gates lenient by that much. The freeze should take its
  baseline with nothing else running; the gate wall times above include suite-lock waits
  (F4b's 654 s cheap gate waited for a slot).

## Tooling and test fixes made during the dry run

- F2 commits the overlap json it used (scripts/split/state/f2-overlap.json); port_branch re-splits F2 with exactly those edges
- codemod applies the surface snapshot to class-mode manifests too (game facade kept 292 imported names off)
- surface test counts the package __init__ as a defining module (Game stays in models/game/__init__)
- hygiene check (d) resolves facade names through sibling packages too (machines/effects/ after F1)
- baselines test count gate excludes the split's own tests (F2 adds tests/test_dispatch_order.py)
- F2 regenerates the committed dispatch fingerprint baseline; F3/F4 compare the fingerprint against it plus pre-split results and chain sets
- gates --keep <json> saves the gate's measurement for the freeze record
- manifest_lib reads a split module's source from the commit that deleted it (manifest tests stay green after F1)
- suite time gate fails on a slowdown over 5%, not on a faster run
- suite measurement records the failing test ids, the gate names them
- Chain.run calls a cached straight-line runner per segment (F2 effects sweep 5.75s -> 5.58s vs 5.40s monolith)
- timing gates compare CPU time when both sides measured it (r2: load 36 on 12 cores doubled wall time at F3, CPU time unchanged)
- import CPU time is the minimum of 7 runs (r4: median of 5 moved +14.6% with machine load)

```sh

$L -- mise run split:baselines -- measure --full --out /tmp/split-before.json

$L -- mise run split:gate -- full  --baseline /tmp/split-before.json --step F2 --keep /tmp/split-F2-full.json
mise run split:step -- F3
$L -- mise run split:gate -- cheap --baseline /tmp/split-before.json --step F3 --keep /tmp/split-F3-cheap.json
```
