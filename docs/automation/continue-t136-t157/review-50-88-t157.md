## real-minor

2. #50 `tests/scenarios/test_discarded_card_free_cast.py` (whole file) and `src/magic_cards_model/machines/effects/draw_discard.py:3165-3246`: only Malcolm's exact sentence is exercised. The spell rung (`s21`, `for_spell=True`), the "that card" alternative, the paying variant (`pays_mana_cost=not free`) and the unconditional form have no test and no real card (baseline shows no text other than Malcolm's matches). The PR body says "the head, the condition and the paying variant are varied in the set": the paying variant is not. Probe: the reader accepts "Each player discards a card. You may cast the discarded card without paying its mana cost." and "Target opponent discards a card. You may cast that card." and would offer other players' discarded cards to the controller (`newly_discarded(game, before)` with no username, `draw_discard.py:3207`). Either cover these with real printings/scenarios or narrow the reader to what is proven (ability side, controller's own discard, condition optional) per the repo "no unproven code" stance; fix the PR body claim either way.
3. #50 Malcolm corner case left as strict xfail: `test_malcolm_gone_before_resolution_uses_its_last_known_counters` (`test_discarded_card_free_cast.py`, last test). Scryfall ruling 2023-11-10: if Malcolm is gone at resolution you still loot and may cast if it had 4+ chorus counters when last on the battlefield (CR 608.2h confirmed). The engine already has `last_known_counters` and `conditions/objects._counters_of(state, past=)`; `_there_are_counters_on` (objects.py:261) never uses it. The xfail is the sanctioned mechanism and is documented in MEMORY.md and engine-coverage.md, so not a blocker, but it is a known wrong result on the very card of the task; a fix in `_there_are_counters_on` (use last known counters when the subject is the ability's source and left the battlefield) is small. Lead decides: fix now or follow-up.
4. #88 `src/magic_cards_model_api/app.py:2538-2540` and `:2558-2560` (callers of `engine_api.parse_counter_kind`): a PATCH with several counters applies them one by one, so `{"chorus": 1, "bad!": 1}` returns 400 but chorus is already set (reproduced with a throwaway test in the scratchpad; also `damage`/`face_up` are applied before). Pre-existing pattern, but the MTGO import sends many counter names in one PATCH and the validation surface just grew. Parse all kinds first, then set.
5. #88 `tests/test_patch_named_counters.py`: no test that a rejected multi-key PATCH leaves state untouched (follows from 4) and none for duplicate keys differing only in case/space (`{"Chorus": 1, "chorus": 2}` silently last-wins, 200).

## nit

6. #88 `engine_api.py` `_COUNTER_NAME`: accepts names with no letter or digit (`"+"`, `"///"`, `"'"`); harmless (colon and control characters, which would collide with `counters_removed:<kind>` fact keys, are rejected) but `[a-z0-9]` required once would be tighter. No cap on the number of distinct kinds per request.
7. #50 `src/magic_cards_model/models/game/_conditions.py:1889-1895`: the "opened" lookup is dead code (shadowed by `conditions/objects._there_are_counters_on`/`_has_counters`); the change has no behaviour effect, so the PR body line "the last closed lookup ... is opened" overstates it. Deleting the shadowed branch would be the simpler diff.
8. #50 untested corner cases of Malcolm's ability: madness card discarded (goes to exile, offered by `newly_discarded` while the madness trigger also exists), X spell discarded (ruling: X must be 0), card with a mandatory additional cost. Shared `may_cast_during_resolution` presumably handles them; not proven here.
9. #50 `tests/dispatch_fingerprint_baseline.json`: additive, consistent with the new rungs and Malcolm's texts; no sign of hand edits beyond what the fingerprint task produces (not regenerated here).

## Checked and fine

- Counter kinds are open per CR 122.1 ("Counters with the same name or description are interchangeable"; 122.1a-j list only special kinds): the engine already keys `Counters` as `dict[str, int]` with `CounterKind = Counter | str` (`models/game/../card_state.py:215-310`, docstring says any name is legal). The fix is the API's validator, not a one-string addition. `parse_counter_kind` trims, lower-cases, returns the enum for known names ("Poison" -> `Counter.POISON`), else the string.
- Validation still rejects: empty, whitespace-only, 41 chars, newline, `<script>`, `;`, `!`, non-ASCII, double spaces (all 400). Probed: "double strike", "-1/-1", 40-char name, "KI" accepted. Error message uses `!r` so no raw injection into the response; audit record runs after validation.
- Persistence: `Counters` is a RootModel of plain `{kind: count}`; scenario harness replay (dump/decode/re-dump) covers string kinds; no model field added, so no `Game.CURRENT_SCHEMA_VERSION` bump needed (stays 178) and the PR states so.
- Malcolm oracle matches Scryfall exactly (trigger puts the counter, draws, discards, then conditional free cast); printing file carries the Scryfall data, Modern legal. Corner cases covered and passing (16 tests, 1 xfail): exactly 4 after the new counter, fewer than 4, more than 4, first hit, decline, discarded land never castable (CR 305.9 and ruling), older graveyard card not castable, counter removed in response. Second uncommon kind: Blademane Baku "ki" (real printing, existing golden).
- No mocks: real printings and the Scenario harness throughout; goldens not hand-edited (none touched; see blocker 1). Test files ran green here (`-n 2`: 15 passed, 1 xfailed).
- #88 safe: change limited to `parse_counter_kind` plus doc strings; 16 API tests pass here including PATCH with `chorus` on a card and `rad` on a player, zero-removal, negative still 400.
