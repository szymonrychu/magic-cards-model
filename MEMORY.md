# Project memory

Standing conventions and corrections, recorded as they came up. One memory
per file in `memory/`, indexed here. New memories go in this directory and
this index - not into any per-user directory - so the project stays the single
home of its own memory.

CR 120.3 is a list of results that "may have one or more" apply, not a dispatch table, so the fix is per-type branches with no fallback: planeswalker -> loyalty counters off, creature -> damage marked, both -> both, neither -> nothing. Two sites, not one: `machines/effects.damage_the_attacked_player` (Hellrider) *also* returned early on a planeswalker defender, citing the same missing rule, so the fix in `deal_damage` alone would have left the card still half-dead

Two files, one seam: `machines/combat._computed_keywords` built its reading vocabulary as combat's own `Keyword` list plus the single word being asked about, and `machines/abilities._parse_keywords` is all-or-nothing, so `protection from instants` - a word that vocabulary did not have - discarded flying and trample with it and the line fell through as an `UnparsedAbility` with nothing recorded. Six printings lost a printed combat keyword this way, and the same line answered two ways depending on the question: `has_keyword(Ketramose, "indestructible")` was True while `has_keyword(Ketramose, "menace")` was False, same card, same board, same line. The wrong assumption was written down at `layers._KNOWN_KEYWORDS` ("`has_keyword` adds the word it is asked about, so a granted line is found by whoever asks") - true only for a line holding nothing but that keyword. **The fix is the vocabulary, never the all-or-nothing rule**: `_reading_vocabulary` adds the permanent's own computed `CardState.keywords`, which is permission to *recognise* a word the computed text already says and grants nothing (a face-down permanent, CR 708.2, still contributes none and still has none). Two traps make relaxing `_parse_keywords` into a partial parse actively wrong, and both are real printings in the pool: Extinguisher Battleship's `5+ | Flying, trample` is CR 721.2a's station symbol, conditional on five charge counters, so keeping the `trample` a partial reader can match would be a fabricated unconditional grant; and Nevinyrral, Urborg Tyrant's `Hexproof from artifacts, creatures, and enchantments` is CR 702.11f shorthand for three abilities, of which a partial read keeps one. Both still fail closed, and now record a `KeywordLineNotice` naming the unread tokens instead of vanishing. Also not adding `protection`/`ward` to `combat.Keyword`: that enum is iterated at `layers._keyword_counter_lines` as CR 122.1b's grantable keyword counters, so a member there mints a counter this engine has no business minting. Schema bumped 4 -> 5, because a version-4 snapshot is a board where Emrakul has no flying.
