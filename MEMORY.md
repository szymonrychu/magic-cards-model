# Project memory

Standing conventions and corrections, recorded as they came up. One memory
per file in `memory/`, indexed here. New memories go in this directory and
this index - not into any per-user directory - so the project stays the single
home of its own memory.

- Damage to a planeswalker was a missing *damage result*, not a missing state-based action - 2026-09-08. The report blamed "the damage-to-loyalty state-based action"; there is no such action. CR 120.3c / CR 306.8 remove the loyalty counters as a **result of the damage event itself**, immediately, and only the graveyard move (CR 306.9 / CR 704.5i) is a state-based action - and that half already worked, which is why the walker sat at `loyalty=9` through every subsequent priority pass looking like an SBA that never fired. The real cause was one line: `Game.deal_damage` ended `else: target.mark_damage(...)` for every non-player target, so a planeswalker collected marked damage (`dmg:9` on the board line) that no rule reads. CR 120.3 is a list of results that "may have one or more" apply, not a dispatch table, so the fix is per-type branches with no fallback: planeswalker -> loyalty counters off, creature -> damage marked, both -> both, neither -> nothing. Two sites, not one: `machines/effects.damage_the_attacked_player` (Hellrider) *also* returned early on a planeswalker defender, citing the same missing rule, so the fix in `deal_damage` alone would have left the card still half-dead

- A readable clause killed by a rider nobody reads, and the two "fixes" that would have looked right — 2026-09-09. Two unrelated readers under one symptom (a strict prefix parses, the whole clause does not). (1) `_CLAUSE_SEPARATOR` eats "then" only as an infix, so a sentence-initial "Then" survived `split_effect_clauses` glued to the clause it introduces; stripping it after the split is sound because CR 608.2c's "in the order written" is all the word states. (2) An **object** anaphor ("It ...", "They ...", "... on it") reached no parser at all - `_ANAPHORIC_SUBJECT_RE` reads only player anaphors - so CR 608.2c's fail-closed guard correctly threw the readable half away, silently. Three traps, each of which produces a card that scores `handled` while doing the wrong thing: **never relax the guard** (Wrath of God would let regeneration through, Kaito would tap without the stun counters); **Ancient Stirrings looks fixed and is dead** without the second, unrelated fix to `_quality_word_matcher`, which read a colour word only as an adjective in front of a type, so bare "colorless" matched nothing and the card bottomed all five cards legally; and **do not widen `machines/layers._SUBJECT` to accept "it"** - `_is_layer_effect_text` is an any-sentence test over the whole ability, so The Wandering Emperor's entire `+1` would route to `create_continuous_effect_of_ability`, granting first strike and never placing the counter. Riders split in two: sequential ones act on the referent afterwards, and CR 608.2c's own worked example ("It can't be regenerated") *modifies* its antecedent instead, so it re-runs the destruction with the prohibition attached. Two subsystems had to be built for the riders not to be untestable no-ops - stun counters (CR 122.1d, inside `CardState.untap`) and regeneration shields (CR 701.19a, through `applicable_effects` so CR 616.1 orders them, with CR 701.19c's prohibition on the *event* rather than the permanent, since it skips a shield rather than spending it)
