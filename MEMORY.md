# Project memory

Standing conventions and corrections, recorded as they came up. One memory
per file in `memory/`, indexed here. New memories go in this directory and
this index - not into any per-user directory - so the project stays the single
home of its own memory.

- [No mocks, scenario tests only](memory/no-mocks-scenario-tests.md) — every test uses real Scryfall cards through the Scenario harness; mocks are banned
- [Never recall MTG rules from memory](memory/never-recall-mtg-rules-from-memory.md) — every rule and CR number must be verified with knowledge_search; training data is wrong
- [magic-cards-model is a rules engine](memory/magic-cards-model-engine-goal.md) — the target is playable PvP MTG, not a card database
- [Subagents on the cheaper model](memory/subagents-on-cheaper-model.md) — pass model: "sonnet" on every Agent dispatch unless told otherwise
- [Engine fixes land in the engine](memory/engine-fixes-in-engine-only.md) — no API/frontend workarounds for rules gaps; only the most correct engine implementation
- [User examples become test cases](memory/user-examples-become-testcases.md) — every play-testing example the user reports is converted to a scenario test
- [Restart the API server after fixes](memory/restart-api-server-after-fixes.md) — uvicorn caches code at boot; kill by port (lsof -ti :8000), and verify the serving process predates no fix
- [Silent-default dispatch tables](memory/silent-default-dispatch-tables.md) — every defect class the loop has found is a lookup that defaults instead of refusing; fail closed and shout on a miss
- [Effect registry is the dominant gap](memory/effect-registry-is-the-dominant-gap.md) — most cards resolve and do nothing; the measured survey, per-deck dead-card counts, and the ranked order of work
- [Verify agent findings against the engine](memory/verify-agent-findings-against-the-engine.md) — adjudicators and reviewers each produce confident wrong claims; reproduce before acting
- [Harness deadlock defaulted every decision](memory/harness-deadlock-defaulted-every-decision.md) — 18 decisions per game timed out unanswered; re-check past "engine did nothing" reports
- [Autonomous playtest loop](memory/autonomous-playtest-loop.md) — play, report, confirm with opus, fix globally with sonnet, repeat until three clean games per deck pair
- [No commits: git checkout destroys work](memory/no-commits-git-checkout-destroys-work.md) — this repo has zero commits, so git restore/checkout/stash overwrite with an ancient index blob; recover from ~/.claude/file-history
- [Agent playtest launch](memory/agent-playtest-launch.md) — two AI players as Agent-tool subagents driving seat_cli.py: sonnet, one-session prompts, no curl (seat hides the opponent's hand), vet their reports against the CR
- [Combat declarations skip the live provider](memory/combat-declarations-skip-the-live-provider.md) — resolved 2026-09-07 (T8) by deleting DecisionScript.provider entirely, not by wiring it up; every asker in machines/decisions.py now answers one way (script, tape, pause, default)
- [Delayed trigger serialization vs. a game.py isolation lock](memory/delayed-trigger-serialization-game-py-isolation.md) — DelayedTrigger.effect became a discriminated union while game.py was locked; a narrow before-validator plus singleton-named specs bridge its 3 legacy call sites instead of blocking
- [KeywordActivation round trip and object identity](memory/keyword-activation-round-trip-identity.md) — typing AbilityOnStack.keyword_activation/.unless_payment correctly still left a decoded KeywordActivation.card as a copy, not the battlefield object; _equip_effect mutated the copy until it re-resolved by id
- [could_pay_mana_cost predicate](memory/could-pay-mana-cost-predicate.md) — the pure affordability predicate could not build a CostPayment at all (for_total registers a pool into open_payment_pools); _SpendContext duck-types its three read-only fields instead, and Card became frozen=True to make the new ability-parse caches sound
- [Flow-based auto-tap source grouping](memory/flow-based-auto-tap-source-grouping.md) — max-flow replaced auto-tap's exponential search, but only after grouping a permanent's several abilities into one provider node; two independent nodes for Eldrazi Temple's {C}/{C}{C} let capacities sum (1+2=3 from one land, one {T})
- [Legal actions enumeration](memory/legal-actions-enumeration.md) — legal_actions never gates on affordability (CR 118.6); why_cannot_cast_now waved a land through with no type check (now refused at the source, Casting itself, CR 305.1); hoisting _auto_tap_candidates needed a spend-independent/spend-dependent split, not just a cache; PERMISSION/STATIC alt-costs are ported into Game.alternative_costs_for and a targeted off-battlefield activation (Boseiju's Channel) reports UNKNOWN instead of vanishing — both were wrongly deferred first pass, fixed second pass
- [Game.schema_version fails closed](memory/game-schema-version-fail-closed.md) — a required no-default field plus a mode="before" validator refuses a mismatched or missing version; the exception subclasses RuntimeError, not ValueError, because pydantic-core rewraps ValueError into a generic ValidationError and would swallow it
- [Scenario round-trip/replay invariant](memory/scenario-round-trip-replay-invariant.md) — every scenario now proves it round-trips and replays; found ~30 Game/token/keyword methods minting ids with no `_id_allocator_scope` open (ids.py's own list was incomplete), an unseeded `random.Random(None)` in cascade's bottoming, a copy-of-a-permanent-spell that never actually became a TokenState, and DecisionScript.provider crashing model_dump with no exclude=True; a global default-allocator design was tried and reverted for breaking legal_actions' purity guarantee
- [Callables became discriminated unions](memory/callables-became-discriminated-unions.md) — 2026-09-07. A keyed registry still defaults silently on an unknown key at decode; a discriminated union on `kind` refuses instead, and carries the closure's own captured parameters as typed fields, which a string key never could
- [Pause is a snapshot plus a tape](memory/pause-is-snapshot-plus-tape.md) — 2026-09-07. Not a `pending` field on `Game`: a half-applied mid-resolution game is not a legal state to persist, so a paused game is (last committed Game, the command, the answers so far) and resuming re-derives the identical decision via ids.py's deterministic allocator
- [Announcement is atomic](memory/announcement-is-atomic.md) — 2026-09-07. `Casting.model_post_init` runs every refusal (CR 305.1, CR 117.1a, restrictions) before CR 601.2a ever moves the card to the stack, so an illegal cast is refused with a reason instead of half-applied
- [DecisionPending is a BaseException](memory/decision-pending-is-a-baseexception.md) — 2026-09-07. Measured: 3 real `except Exception:` sites and 42 real `except ValueError:` sites in `src/` around effect resolution; any of them catching an `Exception`-derived pause would silently turn it into "the effect did nothing", so it derives from `BaseException` instead
- [Exile is a shared zone](memory/exile-is-a-shared-zone.md) — 2026-09-07. `player.add(state, Zone.EXILE)` builds a per-player exile pile the rules have no name for (CR 400.1, CR 406.2); it is invisible to `Game.exile`, to `all_targetables`, and to every seat's board, and `Player.cards_in(Zone.EXILE)` hides it from tests
- [Exile is a shared zone: the full sweep](memory/exile-is-a-shared-zone.md) — 2026-09-08. Nine sites, not five (cascade, Possibility Storm, Wish, Hex Magic, Interdimensional Web Watch and Gemstone Caverns wrote into a per-player pile; three more read one). `Player.zones` is now a `PlayerZones` and `cards_in`/`add`/`move` raise `SharedZoneError` (CR 400.1) instead of minting the pile a read used to create, which is what hid every instance from its own tests — the api's `_all_targetables` had the same defect
- Leaves-the-battlefield triggers fired on one route in five — 2026-09-08. `Game.put_into_graveyard` emits `LEAVES_THE_BATTLEFIELD` *before* moving the card; `exile_permanent`, `return_to_hand`, `put_cards_into_library`, and `ante` all emit it *after*. `machines/triggers._LOOK_BACK_EVENTS` (CR 603.10a's own look-back list) did not name the event, so `zones_ability_functions_in`'s plain-battlefield default only ever matched the pre-move emit — the graveyard route worked by accident, the other four were silently refused. No scenario test anywhere had sent a *printed* leaves-the-battlefield ability through a non-graveyard route; two tests that looked like coverage (`test_trigger_events.py`'s exile/hand pair) only proved `Game.emit` raises the event, through a `DelayedTrigger` watcher that bypasses the zone gate entirely. Fixed by adding `TriggerEvent.LEAVES_THE_BATTLEFIELD` to `_LOOK_BACK_EVENTS`. `put_cards_into_library` also had no `_id_allocator_scope` at all — a second, unrelated pre-existing defect the new tuck-route test exposed via the round-trip/replay invariant, fixed alongside it
- Damage to a planeswalker was a missing *damage result*, not a missing state-based action - 2026-09-08. The report blamed "the damage-to-loyalty state-based action"; there is no such action. CR 120.3c / CR 306.8 remove the loyalty counters as a **result of the damage event itself**, immediately, and only the graveyard move (CR 306.9 / CR 704.5i) is a state-based action - and that half already worked, which is why the walker sat at `loyalty=9` through every subsequent priority pass looking like an SBA that never fired. The real cause was one line: `Game.deal_damage` ended `else: target.mark_damage(...)` for every non-player target, so a planeswalker collected marked damage (`dmg:9` on the board line) that no rule reads. CR 120.3 is a list of results that "may have one or more" apply, not a dispatch table, so the fix is per-type branches with no fallback: planeswalker -> loyalty counters off, creature -> damage marked, both -> both, neither -> nothing. Two sites, not one: `machines/effects.damage_the_attacked_player` (Hellrider) *also* returned early on a planeswalker defender, citing the same missing rule, so the fix in `deal_damage` alone would have left the card still half-dead
- [A substring guard inverted a whole class of triggers](memory/nontoken-substring-guard-inverted-triggers.md) — 2026-09-08. `"nontoken"` contains `"token"`, so a plain `"token" in lowered` guard demanding the entering permanent be a token matched "nontoken artifact"/"nontoken Dragon" too and inverted Weapons Manufacturing's and Miirym's triggers; a word-boundary test alone stops the false match but does not enforce the restriction. `scripts/sweep_pool.py` never calls `condition_matches`, so a trigger whose condition can never match still scores `handled`
- [The sweeper measured effects, never trigger registration](memory/sweeper-measured-effects-not-trigger-registration.md) — 2026-09-08. `scripts/sweep_pool.py` never called `condition_matches`, so a trigger whose condition can never match still scored `handled` (Weapons Manufacturing and Miirym, both fixed on `main` by the nontoken substring fix above) and a fallback parser's answer could come from inside a quoted span rather than the clause's own text; two new closures (`_condition_can_fire`, `_effect_matched_inside_quotes`) catch both, tracked as buckets distinct from `silent`. Ygra, Eater of All and Blade of the Bloodchief hit a different, still-open gap in `condition_matches`'s `DIES` branch: a condition naming neither a self-reference nor "another"/"other" never matches anything
- Into the Flood Maw's "gift was promised" clause was two independent defects, not one - 2026-09-09. `machines/targeting.py`'s `_parse` counted the card's own conditional replacement clause ("If the gift was promised, instead return target nonland permanent ...") as a *second* required target, so a legal single-target cast was refused with "too few targets: 1 chosen where the spell requires 2" (CR 601.2c actually says a spell has alternative targets "only if" the alternative cost was chosen - never both at once, CR 702.174m). Fixing only that left the card castable but inert: `machines/effects.py`'s `_parse_mixed_clauses` had no shape for the second sentence either, so the whole card resolved with no effect at all, silently. Both needed their own fix - `TargetRequirement.if_gift_promised` / `TargetingProfile.for_gift_promise` (targeting) and `_parse_gift_promised_return_instead_clause` (effects, mirroring the existing Fatal Push Revolt-line precedent: the conditional half is enforced by the targeting layer, not re-checked at resolution). Gift itself is still not a payable additional cost (`ADDITIONAL_COST_KEYWORDS` has no "gift" entry), so the promised branch is unreachable from a real cast and is covered by a strict `xfail` in `tests/scenarios/test_gift_targeting.py` rather than a passing scenario
- "As though it had haste" is not the haste keyword — 2026-09-09. A seat piloting Devoted Combo could not tap a summoning-sick Devoted Druid under Tyvar, Jubilant Brawler and filed it under the "Timing restrictions on an activated ability" gap (CR 602.5b/d/e). Wrong bucket: that row is fail-open timing, and the real gap was that nothing read Tyvar's static at all. CR 609.4 - "This applies only to the stated effect" - is what makes the fix narrow: the stated effect is *activating abilities*, so only CR 702.10c's clause is borrowed and CR 702.10b's attacking clause is not, and the creature never gains the keyword, so `machines/combat.has_keyword` and `can_attack` must stay untouched. Granting haste in layer 6 instead would have been the plausible-and-wrong fix: it would have let the Druid attack. Read as a shape at `Game.activation_haste_permission`, the permission twin of `_activation_prohibition`, with `_record_unread_prohibition` renamed `_record_unread_static_line` because a permission read as silence is the same class of defect as a prohibition read as permission
- "Return target `<quality>` card from your graveyard to the battlefield." had no reader — 2026-09-09. The bare singular sentence (no self-reference, no "all", no trailing decoration) was the one shape `_RETURN_FROM_YOUR_GRAVEYARD_TO_HAND_RE`'s battlefield twin never got; fixed with `_RETURN_FROM_YOUR_GRAVEYARD_TO_BATTLEFIELD_RE` / `return_ability_targets_to_battlefield`, closing Unearth, Renegade Rallier, and Tameshi, Reality Architect. Reanimating Renegade Rallier for real surfaced a second, independent gap: `machines/triggers.intervening_if_holds` had no reader for Revolt's own intervening-*if* wording ("a permanent left the battlefield under your control this turn") — Fatal Push's Revolt is read by `targeting.py`'s `comparison_value_if_revolt` because it modifies a target restriction, a completely different code path from a triggered ability's intervening if, so Renegade Rallier's ETB failed closed even with Revolt genuinely active. Fixed via `_REVOLT_CLAUSES`, sharing `Game.revolt_active_for`. `_MASS_RETURN_FROM_GRAVEYARD_TO_BATTLEFIELD_RE` gained an optional trailing " tapped" (CR 110.5b) for Aftermath Analyst. Persist (the sorcery, same five-card template) is deliberately not shipped: its "with a -1/-1 counter on it" is a CR 614.1c enters-with replacement, not add-after — recorded in `docs/engine-coverage.md`'s Not-modelled table instead. Separately verified and ruled *not* mine: a live-game report of Postmortem Lunge reading an announced X as 0 during targeting turned out to be a caller-ordering bug (choosing targets before announcing X) — `test_postmortem_lunge.py` already proves the engine's own `Casting` API is correct in CR 107.3a's order, and an activated ability (Tameshi included) can never hit this window at all since `x_value` and `targets` are announced in the same call.
